## 1. 设计目标

**让合规负责人在 5 分钟内完成自定义配置，不需要任何技术背景。**

v2 扩展目标：

| 目标 | 说明 |
|------|------|
| **零技术门槛** | 用自然语言描述规则，不写代码、不选标签、不配引擎 |
| **5 分钟配置** | 从打开配置页面到规则生效，不超过 5 分钟 |
| **全文档类型覆盖** | 同一套规则框架支持合同、营销物料、金融文档等所有类型 |
| **规则安全性** | 自动检测规则之间的逻辑冲突，防止矛盾规则导致审查结果混乱 |
| **即时生效** | 规则保存后，下一次审查即可使用，无需重启或部署 |

### 2.1 禁用词管理

```
┌─────────────────────────────────────────────────────────────────┐
│  禁用词管理                                                      │
│                                                                  │
│  操作方式: 直接输入词表，一行一个                                  │
│                                                                  │
│  ┌────────────────────────────────────────────────────────┐     │
│  │  禁用词列表                                    [+ 批量导入] │  │
│  │  ──────────────────────────────────────────────────── │     │
│  │  躺赚                                          [删除]  │     │
│  │  暴涨                                          [删除]  │     │
│  │  无脑定投                                      [删除]  │     │
│  │  稳赚不赔                                      [删除]  │     │
│  │  竞品公司A名称                                 [删除]  │     │
│  │  ...                                                   │     │
│  │  ────────────────────────────────────────────────────  │     │
│  │  [输入新禁用词...]                              [添加]  │     │
│  └────────────────────────────────────────────────────────┘     │
│                                                                  │
│  匹配方式:                                                       │
│  · 精确匹配 (默认) — 内容中包含该词即触发                         │
│  · 模糊匹配 (可选) — 允许中间插入空格/标点/零宽字符                │
│                                                                  │
│  匹配引擎: Aho-Corasick 多模式匹配                                │
│  性能: O(n), n=内容长度, 与禁用词数量无关                          │
│  延迟: < 1ms (万级禁用词表)                                       │
│                                                                  │
│  适用范围:                                                       │
│  · 可配置适用的文档类型 (全部 / 仅营销 / 仅合同 / 自选)            │
│  · 默认: 适用于所有文档类型                                       │
│                                                                  │
│  触发行为:                                                       │
│  · 命中禁用词 → 在快速过滤阶段直接标记违规                        │
│  · 不需要进入 LLM 审查流程                                       │
│  · 审查结果中标注: "命中企业禁用词"                                │
└─────────────────────────────────────────────────────────────────┘
```

## 3. 规则执行位置

### 3.1 快速过滤阶段

在 LLM 调用之前的轻量级预处理阶段执行，特点是**快速、确定性、不依赖 LLM**。

| 规则类型 | 快速过滤阶段的行为 | 延迟 |
|----------|-------------------|------|
| 禁用词 | Aho-Corasick 多模式匹配，命中即标记违规 | < 1ms |
| 必备声明 (精确匹配) | 字符串包含检查 | < 1ms |
| 必备声明 (语义匹配) | Embedding 相似度计算 | 50-100ms |
| 合同条款模板 (关键词) | 关键词/布尔表达式匹配 | < 1ms |
| 合同条款模板 (语义) | Embedding 相似度计算 | 50-100ms |

### 3.2 LLM Prompt 阶段

在 ACE 上下文组装阶段加载到 LLM prompt 中，由 LLM 进行语义理解和判断。

| 规则类型 | LLM Prompt 阶段的行为 |
|----------|----------------------|
| 产品信息绑定 | 产品信息注入 prompt，LLM 检查内容与产品信息的一致性 |
| 自然语言规则 | 规则文本直接拼入 prompt 的"企业特殊要求"区块 |
| 合同条款模板 (LLM语义理解) | 检查指令拼入 prompt，LLM 理解并执行检查 |

### 3.3 执行位置总览

```

  │                     │     │                           │
```

## 4. 规则冲突检测 (v2 新增)

### 4.1 设计动机

随着企业自定义规则数量增加（尤其是合同条款模板和自然语言规则），规则之间可能出现逻辑矛盾。例如：

- 规则 A: "所有合同必须包含自动续约条款"
- 规则 B: "合同不得包含无限期自动续约条款"
  → 这两条规则本身不矛盾（一个要求有续约，一个禁止无限期续约），但如果规则 A 没有限定"有期限的"，就可能导致审查结果混乱

- 规则 C: "违约金不得超过合同额的 200%"
- 规则 D: "服务合同的违约金不得超过合同额的 100%"
  → 对服务合同，两条规则同时适用，应以更严格的规则 D 为准

如果不检测冲突，可能出现：
1. 同一条款被一条规则判定为合规、被另一条规则判定为违规
2. LLM 收到矛盾的指令后产生不确定的输出
3. 审核人对审查结果产生困惑

### 4.2 冲突类型

```
┌──────────────────────────────────────────────────────────────────────┐
│  规则冲突类型                                                         │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────────┐ │
│  │  类型1: 直接矛盾 (Contradiction)                                │ │
│  │                                                                │ │
│  │  定义: 两条规则对同一对象给出相反的要求                          │ │
│  │                                                                │ │
│  │  示例:                                                          │ │
│  │  规则A: "合同必须包含竞业限制条款" (must-have)                  │ │
│  │  规则B: "劳动合同不得包含竞业限制条款" (must-not-have)          │ │
│  │  → 当文档类型为"劳动合同"时，两条规则直接矛盾                  │ │
│  │                                                                │ │
│  │  检测: 对同一文档类型 + 同一条款主题，                          │ │
│  │       如果同时存在 must-have 和 must-not-have → 直接矛盾        │ │
│  │  严重程度: ❌ 严重 — 必须在规则保存前解决                       │ │
│  └────────────────────────────────────────────────────────────────┘ │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────────┐ │
│  │  类型2: 范围重叠 (Overlap)                                      │ │
│  │                                                                │ │
│  │  定义: 两条规则的适用范围重叠，且约束不一致                      │ │
│  │                                                                │ │
│  │  示例:                                                          │ │
│  │  规则C: "违约金不得超过合同额的200%" (适用: 全部合同)           │ │
│  │  规则D: "违约金不得超过合同额的100%" (适用: 服务合同)           │ │
│  │  → 服务合同受两条规则约束，应以更严格的100%为准                 │ │
│  │                                                                │ │
│  │  检测: 两条规则适用范围有交集 + 约束主题相同 + 约束值不同        │ │
│  │  严重程度: ⚠️ 警告 — 建议明确优先级                             │ │
│  └────────────────────────────────────────────────────────────────┘ │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────────┐ │
│  │  类型3: 语义冲突 (Semantic Conflict)                            │ │
│  │                                                                │ │
│  │  定义: 两条自然语言规则的语义存在潜在冲突                        │ │
│  │                                                                │ │
│  │  示例:                                                          │ │
│  │  规则E: "所有营销内容必须突出展示收益率数据"                     │ │
│  │  规则F: "收益率数字的字号不得超过风险提示字号的2倍"              │ │
│  │  → "突出展示" 和 "字号不得过大" 存在紧张关系                    │ │
│  │                                                                │ │
│  │  检测: LLM 辅助判断两条自然语言规则是否存在语义冲突              │ │
│  │  严重程度: ℹ️ 提示 — 建议人工确认                                │ │
│  └────────────────────────────────────────────────────────────────┘ │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────────┐ │
│  │  类型4: 禁用词与自然语言规则冲突                                 │ │
│  │                                                                │ │
│  │  定义: 禁用词列表中的词出现在自然语言规则的"要求使用"范围内      │ │
│  │                                                                │ │
│  │  示例:                                                          │ │
│  │  禁用词: "保本"                                                 │ │
│  │  自然语言规则: "所有基金合同必须包含'基金管理人不保本'声明"      │ │
│  │  → "不保本"包含"保本"，会被禁用词误触                          │ │
│  │                                                                │ │
│  │  检测: 检查禁用词是否为某条必备声明或自然语言规则的子串          │ │
│  │  严重程度: ⚠️ 警告 — 禁用词可能误触                              │ │
│  └────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────┘
```

### 4.3 冲突检测引擎

```
┌──────────────────────────────────────────────────────────────────────┐
│  冲突检测引擎                                                         │
│                                                                      │
│  触发时机:                                                           │
│  1. 用户保存新规则时 → 实时检测 (保存前拦截)                          │
│  2. 每日定时扫描 → 全量检测 (覆盖跨类型冲突)                          │
│  3. 文档类型注册表变更时 → 增量检测                                    │
│                                                                      │
│  检测流程:                                                           │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────────┐ │
│  │  Step 1: 规则规范化                                             │ │
│  │                                                                │ │
│  │  将所有规则统一为结构化表示:                                     │ │
│  │  {                                                              │ │
│  │    rule_id: "R001",                                             │ │
│  │    type: "must_have" | "must_not_have" | "constraint" |         │ │
│  │          "banned_word" | "required_statement",                  │ │
│  │    subject: "数据保护条款",    // 规则约束的对象                  │ │
│  │    scope: ["service_contract"], // 适用文档类型                  │ │
│  │    constraint_value: null,     // 数值约束 (如有)                │ │
│  │    natural_text: "...",        // 原始规则文本                   │ │
│  │    embedding: [...]            // 规则文本的向量表示              │ │
│  │  }                                                              │ │
│  └────────────────────────────────────────────────────────────────┘ │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────────┐ │
│  │  Step 2: 确定性冲突检测                                         │ │
│  │                                                                │ │
│  │  2a. must-have vs must-not-have 矛盾检测:                      │ │
│  │    FOR each must_have rule M:                                   │ │
│  │      FOR each must_not_have rule N:                             │ │
│  │        IF M.scope ∩ N.scope ≠ ∅:  // 适用范围有交集             │ │
│  │          sim = cosineSimilarity(M.embedding, N.embedding)       │ │
│  │          IF sim > 0.85:  // 约束对象语义相似                     │ │
│  │            → 报告: 直接矛盾 (M, N)                              │ │
│  │                                                                │ │
│  │  2b. 禁用词 vs 必备声明/自然语言规则 误触检测:                   │ │
│  │    FOR each banned_word W:                                      │ │
│  │      FOR each required_statement S:                             │ │
│  │        IF W.text ∈ S.text:  // 禁用词是必备声明的子串           │ │
│  │          → 报告: 禁用词可能误触 (W, S)                          │ │
│  │                                                                │ │
│  │  2c. 数值约束范围重叠检测:                                      │ │
│  │    FOR each constraint rule C1:                                  │ │
│  │      FOR each constraint rule C2 (C2 ≠ C1):                     │ │
│  │        IF C1.scope ∩ C2.scope ≠ ∅                              │ │
│  │          AND sim(C1.subject, C2.subject) > 0.85                 │ │
│  │          AND C1.constraint_value ≠ C2.constraint_value:         │ │
│  │          → 报告: 范围重叠 (C1, C2)                              │ │
│  └────────────────────────────────────────────────────────────────┘ │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────────┐ │
│  │  Step 3: LLM 辅助语义冲突检测                                   │ │
│  │                                                                │ │
│  │  对于自然语言规则，使用 LLM 辅助判断:                            │ │
│  │                                                                │ │
│  │  Prompt:                                                        │ │
│  │  "以下是企业的两条审查规则，请判断它们之间是否存在逻辑冲突       │ │
│  │   或紧张关系。如果存在，请说明冲突点和建议。                     │ │
│  │                                                                │ │
│  │   规则1: {rule_1.natural_text}                                  │ │
│  │   适用范围: {rule_1.scope}                                      │ │
│  │                                                                │ │
│  │   规则2: {rule_2.natural_text}                                  │ │
│  │   适用范围: {rule_2.scope}                                      │ │
│  │                                                                │ │
│  │   请输出: conflict: true/false, reason: '...', severity: '...'"│ │
│  │                                                                │ │
│  │  注意: LLM 检测仅用于自然语言规则之间的语义冲突                 │ │
│  │  确定性冲突 (矛盾、范围重叠) 不依赖 LLM                        │ │
│  └────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────┘
```
